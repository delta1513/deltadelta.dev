How I use AI

I use AI and LLMs for a lot of stuff. The code for this website was almost fully vibe-coded. Even the infrastructure and ops in place for managing my blog is vibe-coded (but the content is all me apart from spell-checks).

In this article, I'm going to take you through some personas that I like to use to describe the different ways I use AI both personally and at work.

The Bootstrapper

If you've ever used tools like Bolt, Lovable or Google's coding agent in their AI studio, you'll be familiar with the capabilities of this persona.

The Bootstrapper is a way I like to use AI to set up a completely new project from scratch.

Depending on the scope of the project I'll either vibe it until completion or use it as a foundation for smaller, more iterative improvements.

For smaller projects, they will often be small and clear enough to encode into the prompt itself, so usually you can one-shot them.

For larger and more professional projects, I like to have a plan of the architecture beforehand. I like to sketch out the systems involved, how everything should interact, and keep in mind how to implement DRYness as I move forward.

The larger projects almost always can't be one-shot, but sometimes you can one-shot the foundations, then you can import it and work with something like cursor to make smaller and more well-architected changes to move the project forward.

If I am fully vibing a large project, I find that the scope of the changes and the amount of code going into the project follows an inverse logarithm, ie, there is significantly less code going in at each iteration so that I can control the quality of the output to ensure it adheres to the architecture and scalability I have in mind.

The Spider

This persona is best explained as a tool similar to Perplexity. I call it a spider because I treat it as my own personal web crawler.

Whenever I want to learn more about something or I'm searching for something exceptionally specific on the web, I'll use either a tool like Perplexity or Gemini deep research.

Then after it goes deep into countless web pages and other data, I often skim over 90% of the output and instead focus on the actual meat that I was looking for. Otherwise I might even just ask for a summary of for it to generate a table of contents so that I can navigate it better.

I'm not interested in an exceptionally written report or a well formed summary of the research, I want the facts and references that I'm looking for. Most of the outputs from these Spiders is either fluff or hallucinated, and I don't want to not only sit and read through it, but I also don't want to remain highly skeptical on every single word that I'm reading.

The Junior

The Junior is an aspiring, young and incredibly smart engineer, and they just joined your company, how exciting! But there's one catch, your manager hasn't given you any time to teach the poor guy the codebase, and we need his help ASAP!

So I set up this Junior with GitHub access, Linear access, the code, documentation, and a notepad to jot down some things that he learns.

Because he is new, I only trust him with really well-scoped tasks with minimal dependencies on stakeholders and external systems. Sometimes I have to hand-hold him, but usually his PRs are pretty good, and it's only on occasion that I leave a few comments for him to iterate on.
